# Implementation Notes

## Что реализовано

- Приложение «Мой рацион» на Python Flet с экранами входа, регистрации, главной страницы, ингредиентов, блюд и статистики.
- SQLite-хранилище с таблицами `users`, `ingredients`, `dishes`, `dish_ingredients`.
- Регистрация и вход пользователя; пароль хранится не в открытом виде, а как PBKDF2-SHA256 с индивидуальной солью.
- CRUD для ингредиентов: добавление, просмотр, редактирование, удаление с проверкой уникальности названия в рамках пользователя.
- Создание и удаление блюд; блюдо собирается из ингредиентов и весов, итоговая калорийность считается автоматически.
- Главный экран с блюдами за сегодня, суммой калорий и рекомендацией.
- Статистика за день, неделю, месяц, год и весь период с группировкой калорий по дням.
- Минимальные pytest-тесты для расчёта калорий, рекомендаций и валидаторов.
- Dockerfile, docker-compose.yml и .dockerignore для запуска Flet как web-приложения на `http://localhost:8550`.
- `flet-cli` добавлен как явная зависимость, чтобы Docker-контейнер не пытался доустановить CLI при старте под непривилегированным пользователем.

## Как устранены противоречия

- В PDF ранняя формула расчёта была записана неоднозначно как умножение калорий ингредиента на количество. Реализована корректная формула: `калории на 100 г * вес в граммах / 100`.
- В требованиях к рекомендациям диапазоны пересекались на значении 2200 ккал. Для MVP принято правило: `1500..2200` включительно считается нормой, а превышение начинается строго больше 2200.
- В PDF упоминается проверка сложности пароля, но конкретные правила не заданы. Для MVP оставлена обязательность пароля и совпадение повтора; это не блокирует основной сценарий и не вводит произвольные требования.
- В сценарии блюда есть добавление нового ингредиента прямо из формы блюда. Для надёжного MVP ингредиенты добавляются на отдельном экране, а форма блюда использует уже существующую базу ингредиентов.
- Редактирование блюда обозначено как желательное. В MVP реализовано создание и удаление блюд; редактирование можно добавить поверх существующего `DishRepository` без изменения модели данных.

## Какие допущения сделаны

- Один ингредиент нельзя удалить, если он уже используется в сохранённых блюдах, чтобы история блюд оставалась консистентной.
- Даты хранятся в SQLite как ISO-строки локального времени приложения.
- Калорийность блюда округляется до двух знаков при сохранении.
- Уникальность ингредиента проверяется без учёта регистра через SQLite-индекс `COLLATE NOCASE`.
- Суточная рекомендация на главном экране считается только по текущей календарной дате.

## Архитектура приложения

- UI-слой: `app/ui`. Содержит Flet-приложение, страницы и небольшие компоненты интерфейса.
- Service-слой: `app/services`. Содержит авторизацию, формулы калорий, рекомендации, статистику и операции каталога.
- Data-слой: `app/db`. Содержит инициализацию SQLite, dataclass-модели и репозитории.
- Utils: `app/utils`. Содержит валидаторы пользовательского ввода.
- Точка входа: `app/main.py`, где сначала инициализируется БД, затем запускается Flet.

## Как запустить проект

Локально:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
flet run app/main.py
```

Linux/macOS:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
flet run app/main.py
```

Тесты:

```bash
pytest
```

Docker:

```bash
docker compose up --build
```

Если образ был собран раньше и Docker использует кеш:

```bash
docker compose build --no-cache
docker compose up
```

Адрес web-приложения:

```text
http://localhost:8550
```
